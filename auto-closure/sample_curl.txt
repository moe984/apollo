Apollo auto-closure: sample curl (PROD)

Endpoint: PATCH https://apollo.cosmos.tekstream.com/api/v1/alerts/{alertId}/workflow-status
Dev:      https://apollo-dev.cosmos.tekstream.com
Auth:     x-api-key (same key as POST /api/v1/ingest/soar); set APOLLO_API_KEY first.

# Auto-close an alert
curl -i -X PATCH "https://apollo.cosmos.tekstream.com/api/v1/alerts/tekstream-950260902/workflow-status" \
  -H "x-api-key: $APOLLO_API_KEY" \
  -H "content-type: application/json" \
  -d '{"status": "auto_closed", "reason": "Duplicate of tekstream-950260901"}'

# Reopen it
curl -i -X PATCH "https://apollo.cosmos.tekstream.com/api/v1/alerts/tekstream-950260902/workflow-status" \
  -H "x-api-key: $APOLLO_API_KEY" \
  -H "content-type: application/json" \
  -d '{"status": "open"}'

Allowed status values:
  open, preparing, under_review, under_investigation, escalated,
  customer_responded, closed, auto_closed
"reason" is optional (max 1000 chars; stored as workflow_status_reason).

Note: auto_closed may only be set on a DUPLICATE (an alert whose parent's dedup
verdict is DUPLICATE). NEW / SIMILAR alerts get 409 not_a_duplicate; use "closed".
