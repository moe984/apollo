Key Findings

  • MITRE ATT&CK mapping is non-deterministic: 8 unique techniques identified across 30 runs, but only 2 (T1105, T1059.001) appeared in every single run. The other 6 techniques appear in 2/30 to 20/30 of runs.
  • Confidence scores vary despite temperature=0: 3 distinct values observed — 0.920 (17%), 0.940 (47%), 0.960 (37%). Near policy thresholds (e.g., 0.95 for auto-close), this variance would cause different policy gate decisions for the same alert.
  • Sub-technique granularity is inconsistent: The LLM can't decide between T1071 (parent) and T1071.001 (sub-technique) — it returns T1071 in 12/30 runs and T1071.001 in 18/30 runs. They never co-occur in the same response.
  • Every run returns exactly 4 MITRE techniques: The first two slots are locked (T1105, T1059.001). The 3rd and 4th slots rotate between the remaining 6 techniques.

Conclusion

At temperature=0, the LLM's binary classification is stable — disposition, FP score, and severity are consistent across 30 runs. However, structured output fields are not deterministic. Confidence scores vary (0.920-0.960), MITRE technique mapping is unreliable (6 of 8 techniques appear inconsistently), and the rationale text changes every run. This means LLMs are acceptable for coarse-grained classification (escalate/close/review) when reinforced by policy gates, but not suitable as the sole source of truth for fine-grained structured data like MITRE ATT&CK mapping, numeric score calibration, or evidence grounding. These tasks should be handled by deterministic systems — rule engines, trained ML classifiers, or lookup-based mappers — that produce identical output for identical input.
