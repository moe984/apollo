# model-training-pipeline

A binary classifier, end to end, in one Jupyter notebook.

**Is this alert a Benign Positive, or is it something else?** That is the whole
question. Benign Positive → the AI closes it; anything else → a human looks. The
model outputs `P(not benign)` and a threshold decides.

```bash
.venv/bin/jupyter lab train.ipynb
```

Kernel: **AI-SOC training pipeline** (`ai-soc-pipeline`, the `.venv` in this
folder).

## What is here

| | |
| --- | --- |
| `train.ipynb` | the whole pipeline — every function is defined in a cell, nothing is imported from a local module |
| `eda.ipynb` | the data underneath the model — what each field contains, how much it tells you about the label, and a step-by-step walkthrough of **how the operating threshold is chosen** |
| `artifacts/v20/` | the frozen release: `model.joblib`, `manifest.json`, `README.md` |
| **`TRAINING_KEYS.md`** | **every one of the 1,312 CEF keys the model is fitted on**, tiered by coverage, with what each contributes and whether Apollo sends it |
| `artifacts/training_keys.csv` | the same list, machine-readable, regenerated by the notebook |
| `.venv/`, `requirements.txt` | Python 3.14, JupyterLab 4.6, scikit-learn 1.9 |

Reading `train.ipynb` top to bottom is reading the entire implementation.

# What the model is trained on

## The input is one string per alert

The model reads **one column, `text_cef`**. No tabular features, no history, no
state. That column is the Splunk ES notable — the alert exactly as it arrived —
flattened to `key value` pairs and lowercased:

```
clientname mcneese _risk_user serviceprincipal_41017223-… action_taken add user.
actor serviceprincipal_41017223-… destinationusername aandrus13@mcneese.edu
akinney@mcneese.edu … entity_type user eventtype modnotable_results notable
risk_notables label generic notable_type risk_event orig_rule_description this
search looks for over 10 user creations in a short timespan. …
rule_name ts - o365 - multiple user creations within short time
security_domain audit severities low severity low urgency low workbook mdr workbook
```

Pairs rather than bare values, so a word bigram can bind a field to its reading —
`severity low` and `urgency low` stay distinguishable.

## Which artifact

A container carries up to four families of artifact and **only one predates the
analyst**:

| Artifact | Test | Used |
| --- | --- | --- |
| **ES notable** | `rule_id` present, `SA_DISPOSITION` absent | **yes — this is the alert** |
| settings/metrics | carries `SA_DISPOSITION` | no — that field *is* the label |
| `soar_event=*` | `incident_closure`, `sa_decision`, … | no — written during triage |
| Slack/escalation | `reply_count`, `snooze_count` | no — only exists once escalated to a human |

The intuitive test — *"no `soar_event` key"* — is **wrong**: two of the four
families lack it, and one of those carries the label itself.

30,830 of 32,429 labelled containers (95.1%) have a readable notable.

the *sample* — one server over two months — rather than from the feed: only 19
of them occur on that server inside that window at all, on 8–9 alerts each.

## What is thrown away

Four rules, in order. Anything not caught is fitted.

**1. The `DROP` set — 44 keys.**

| Group | Keys | Why |
| --- | --- | --- |
| Splunk plumbing | `_bkt` `_cd` `_si` `_indextime` `_sourcetype` `_eventtype_color` | internal storage handles |
| Per-event identifiers | `event_id` `rule_id` `orig_sid` `orig_rid` `source_event_id` `event_hash` | unique per alert — a memorised handle on one training row, never a transferable pattern |
| Timestamps | `_time` `time` `timestamp` `orig_time` `post_time` `receipt_time` `sla_receipt` `info_max_time` `info_min_time` `info_search_time` | encode *when*, not *what* |
| Date parts | `date_hour` `date_mday` `date_wday` `date_year` `date_minute` `date_month` `date_second` `date_zone` | same |
| URLs back to the console | `es_notable_url` `ES_NOTABLE_URL` `container_url` `ES_URL` | per-alert handles |
| ES triage state | `status` `status_default` `status_end` `status_group` `status_label` `status_description` `owner` `owner_realname` | describe triage, which moves **after** the alert arrives |
| **Serving alignment** | `extract_artifacts` `splunk_query` | present on one side only — see below |

**2. `scrub_time` — by value, not by key name.** ISO dates, epochs, bare years and
clock times are removed wherever they appear, including inside filenames and rule
descriptions. A key blocklist cannot catch these: the blob carries timestamps in
at least twenty differently-named fields.

This matters because the not-benign base rate runs from **6.5%** at the start of
the window to **25.3%** at the end. A date is genuinely predictive — of the
*training window*, and of nothing beyond it. The first fit put `2026 04` among its
strongest features. Scrubbing costs 0.0002 ROC.

**3. `NOT_A_VALUE`** — values reading `none`, `null`, `-`, `unknown`.

**4. Never considered at all** — no tabular features (rule and tenant priors lost
to the text), no hour or weekday (a staffing artifact), no identity columns
(including them moved ROC 0.840 → 0.806), no calibration wrapper (cost 0.03 ROC).

## Serving alignment: `extract_artifacts` and `splunk_query`

The model is trained on the SOAR export and served by **Apollo**, which forwards
the ES notable itself in `soar_cef` — not a summary of it. Two keys exist on one
side only:

| Key | Where | Effect |
| --- | --- | --- |
| `extract_artifacts` | SOAR only | a near-constant Splunk config blob, 0.89% of terms |
| `splunk_query` | Apollo only, 46% of records | nothing to train on |

Left in, the same alert scores differently depending on which side built the
string — mean 0.042, max 0.38, against a zero-miss threshold of 0.0014. Dropped,
the two strings are **byte-identical on all 3,533 validated alerts, max score
difference 0.00e+00**, and the out-of-fold ROC is unchanged at 0.8523.

See `../APOLLO_MAPPING.md`.

# The label

| Disposition | Class | `not_benign` | Rows |
| --- | --- | ---: | ---: |
| Benign Positive — Suspicious But Expected | benign | 0 | 25,963 |
| True Positive — Suspicious Activity | not benign | 1 | 5,723 |
| False Positive — Incorrect Analytic Logic | not benign | 1 | 580 |
| False Positive — Inaccurate Data | not benign | 1 | 161 |
| `Other`, `Undetermined`, never dispositioned | *dropped* | — | 91,468 |

False Positive sits with True Positive because it is still not benign — it needs a
human *action*, a detection fix rather than a response. Keeping class 0 to Benign
Positive alone is what makes the negative class mean one clean thing.

Ordering is by **`close_time`** — when a human ruled the container — not by
arrival. The split is a timestamp quantile, so no decision time straddles the
boundary.

# Results

| | Rows | ROC AUC | PR AUC |
| --- | ---: | ---: | ---: |
| out-of-fold, 5 expanding forward folds | 27,023 | **0.8540** | 0.6893 |

Matches `../models/v20`, built by a separate implementation of the same rules.
End to end the notebook runs in about two minutes.

## The two things that define this release

**`ml/v20` fits only the 937 fields Apollo actually sends** — the intersection of
the training corpus and the live feed, from `../config/apollo_keys.json` (copied
into `../models/v20/` when the release is cut). The
other 375 in the corpus would be weights the model can never use at inference.
The restriction costs 0.0001 ROC and buys **18% more coverage at zero misses**.

**And `min_df=1`** — the change that made v18 out of v11 — TF-IDF keeps
terms seen exactly once. The usual reason to drop singletons is that a term seen
once cannot generalise. That is wrong here: a rule name or host identifier
appearing on a handful of alerts is precisely what lets the model be *certain* an
alert is benign, and certainty at the low tail is the only thing the router uses.

| | `min_df=2` (v11) | `min_df=1` (v18/v20) |
| --- | ---: | ---: |
| Vocabulary | 168,679 | **918,956** |
| ROC AUC | 0.8523 | **0.8541** |
| PR AUC | 0.6886 | **0.6900** |
| **Auto-closes at 0 misses** | 0.84% | **1.40%** |
| Auto-closes at 5 misses | 1.71% | **3.10%** |

**67% more of the queue auto-closed with zero mistakes.** That is the largest
operational gain of anything tried, and the only change in many rounds that moved
coverage rather than only AUC.

`binary=True` scores higher still on ROC — 0.8568, the highest measured anywhere —
and was rejected: it collapses zero-miss coverage to 0.12%, sharpening the middle
of the score distribution at the cost of the tail the router operates in.

**Accuracy is the wrong number** — 77.4% of the window is Benign Positive, so
always answering "benign" scores 77.4% and gets every real incident wrong. The
notebook reports coverage at a miss rate instead, plus confusion matrices at both
0.5 and the deployment threshold.

## Two caveats the notebook makes explicit

**Thresholds do not transfer.** The release publishes a zero-miss threshold from
out-of-fold scores across twelve months; the held-out window is the last three,
where the not-benign rate is 22.6%. Applying the published threshold to recent
traffic auto-closes **nothing** while the manifest advertises 0.84%. Ship the
model, recalibrate the operating point on a window that looks like what it will
actually see.

**1,599 containers have no ES notable.** `to_text` returns `""` and the model
scores the empty string rather than refusing. Gate on `alert_keys > 0`.

## The ceiling

Every architecture tried lands in **0.76–0.85** — TF-IDF, gradient-boosted trees,
ATTACK-BERT frozen and fine-tuned, embeddings into SGD. Closing desks disagree by
**15.3 points** on the same rule at the same customer, which sits above all of
them. The label noise is the ceiling, not the feature set.
